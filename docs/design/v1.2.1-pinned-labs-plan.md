whether swarm belongs in T3 at all, and it keeps iterating separately). v1.2.1 is now only the pin

fleet-free, no peer-exec). The fork build branch `release/v1.2.1` is created from that commit and
contains `feat/v1.2.1-pins-on-v1.2.0` (3 commits) and, optionally, `fix/v1.2.0-peer-test-mocks`

## 4. P2: pinned threads fold into Working under the overhaul

Target behavior when the overhaul is on and the Working section is on:
- A working pinned thread sits in Working, sorted by last send.
- When it stops, it gets the same 2-second exit grace (`WORKING_EXIT_GRACE_MS`) and the same
  "returned" ordering as an unpinned thread.
- There is no pinned section.
- Settle stays hidden (D4), and pinning still blocks automatic settling.
- Snoozed and Settled take precedence.
- `pinOrderKey` is kept untouched.

With the overhaul off, nothing changes.

**P2-1. Reproduce (half a day).**
- On a dev server, with the overhaul on, pin a thread and start a long turn. Record the thread's
  section while running, around a continuation, and after it stops, on web and on mobile.
- Also record how many delegated child threads appear in Working during a `delegate_task` fan-out,
  because Swarm v2 adds many live children.
- Expected from the code:
  - Web already routes it into Working. `resolveSidebarThreadSection` returns `active`
    (`Sidebar.logic.ts:169-180`), then `inbox()` runs (`Sidebar.tsx:603-700`).
  - The thread drops out of Working with no grace, because `threadInbox.ts` `excluded` includes
    `pinnedAt != null`.
  - Mobile always shows it in Pinned.
- Write the results in §9. If web behaves differently, revise P2-3 before starting it.

**P2-2. Shared section rule (client-runtime).**
- Add to `packages/client-runtime/src/state/threadInbox.ts`:
  ```ts
  export function resolveInboxSection(input: {
    snoozed: boolean; settled: boolean; pinned: boolean; pinOverhaul: boolean;
  }): "snoozed" | "settled" | "pinned" | "inbox"
  ```
- Web `resolveSidebarThreadSection` calls it, mapping `inbox` → `active`, and keeps its signature and
  tests. Mobile calls it in P2-5.
- **Tests:** a table test in `threadInbox.test.ts`.
