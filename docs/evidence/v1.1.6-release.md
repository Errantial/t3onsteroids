## Linux

`t3-0.1.5-v1.1.6.20261101.72a78e666ea1.connect1-linux-arm64.tar.gz`

- Size: 120,507,825 bytes; 3,629 archive entries.
- SHA-256: `17F1F7B36E1FFED7AAF916DB88A0D9B50DC9F614167A7B20DF124CCF293C95CC`.
- Built natively on server-1 (Oracle Linux 9, aarch64) in a scratch clone with Node 26.12.1 and
  `nice -n 10`, so its T3 kept serving during the build.
- Layout: `t3` launcher, `node` 26.12.1, `t3.mjs` (`apps/server/dist-exe/bin.mjs`), `client/`,
  `node_modules/`, `lib/`, `resource-monitor/linux-arm64/`, `.install-complete`.
- Extracted to a fresh directory and run from another working directory:
  `t3 v0.1.5-v1.1.6.20261101.72a78e666ea1.connect1`.
- Bundled `libatomic.so.1` is `libatomic-11.5.0-11.0.2.el9.aarch64` from Oracle Linux 9. The archive
  builder assumes Ubuntu and asks `dpkg-query` for provenance; server-1 is RPM-based, so the build
  used a host-local `dpkg-query` metadata shim and then rewrote `lib/libatomic.so.1.LICENSE` to name
  the actual Oracle Linux package. The shipped file contains no Ubuntu or Launchpad reference.
  Teaching `bundleLinuxLibatomic` to read `rpm` metadata directly is a v1.1.7 build-tooling item.
- The Windows build host is the Framework; cross-building arm64 there is unsupported (`vp pack` has
  no linux-arm64 target and cross-injected SEA output does not execute), so server-1 is required.
