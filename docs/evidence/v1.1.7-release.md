## Fleet updater notes

- Linux uses the boot service's pinned-runtime path: the release tag and `SHA256SUMS.txt` are passed
  to `ServerSelfUpdate`, which downloads the arm64 archive, verifies it, runs `__service-preflight`,
  and hands the switch to the launcher. The previous runtime directory stays for rollback.
- Windows desktop uses its packaged `electron-updater` feed, which points at
  `Errantial/t3onsteroids` and `latest.yml`.
- A machine must already run v1.1.7 to answer the fleet RPCs and tools. The first rollout of older
  machines still uses `scripts/fleet-update.mjs`; this is stated in the release notes.
- UI and MCP both require confirmation for a real run; `fleet_update` defaults to a dry run. No
  machine is updated by this release.
