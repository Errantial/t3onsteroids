1. **v1.2.1 is pins only, as a point release.** The release is `release/v1.2.0` plus the pin overhaul.
   Because v1.2.0 is already published (2026-11-04, tag `v1.2.0` at `0f128e0`, build commit `92f12598b7`),
   its branch is not changed. A new fork branch `release/v1.2.1` is created from `92f12598b7`, the pin
   branch is merged into it, and it is built and published as v1.2.1. Swarm v2 is not in it.
2. **Backup push** (origin `Errantial/t3code` and `Errantial/t3onsteroids` only; never `upstream`):
   - fork `feat/swarm-wip`: `c5a63adf4952fcdcb042bc98a8dd2aa13d659d52` (new; the swarm work, 71 commits;
     `feat/v1.2.1-on-v1.2.0`, already on origin at `74b4a9644a`, can be advanced to the same commit);
   - fork `fix/v1.2.0-peer-test-mocks`: `82d7ef1355372c6d3a23a054c041c2ba78a765fa` (new);
   - fork `fix/v1.2.0-preview-test-list`: `e107c322be` (new);
   - fork `feat/v1.2.1-pins-on-v1.2.0`: `edb1a4bf587d0576e97265ee7fcd674c83bd2239` (already on origin);
   - bridge `swarm-wip`: `324182e` (new; the full swarm plan, evidence and notes);
   - bridge `release/v1.2.1`: the head of this branch.
3. **Merges into the new `release/v1.2.1`:** the pin branch. Also, recommended, the two test-only fixes.
   They change no runtime code and turn two failing test areas on v1.2.0 green; leaving them out only
   leaves those tests failing as they already do on v1.2.0.
4. **Tag and publish** `v1.2.1` on `Errantial/t3onsteroids`, created as a draft first.
5. **Accept the documented limits:** mobile pin overhaul not checked on a device; the swarm-free build not
   run live before the release (the check is in the commands as step 2b); Linux browser tests not run.
6. **Not included, and needs its own approval:** rolling v1.2.1 out to any machine.

**One-word approval:** reply **GO** to approve decisions 1 to 5 with the two test-only fixes included.
Reply **GO-PINS-ONLY** for the same without the two test-only fixes. Reply **GO-BACKUP** to approve only
the backup push in decision 2. Anything else, nothing runs.

### Commands

Placeholders: `BUILD` is the head of fork `release/v1.2.1` after the merges, `BUILD12` its first 12
characters, `DATE` is `YYYYMMDD` (UTC), and `FULL` is the full version.

```sh
# 0. Backup push (decision 2). Remotes: origin only.
git -C <fork> push origin feat/swarm-wip fix/v1.2.0-peer-test-mocks fix/v1.2.0-preview-test-list
git -C <fork> push origin feat/v1.2.1-on-v1.2.0        # fast-forward to c5a63adf49
git -C <bridge> push origin swarm-wip release/v1.2.1

# 1. New fork build branch from the published v1.2.0 build commit (decisions 1 and 3).
cd <fork>
git fetch origin
git switch -c release/v1.2.1 92f12598b70619dbb9af9ec4827a7660a2aea40b
git merge --no-ff feat/v1.2.1-pins-on-v1.2.0
git merge --no-ff fix/v1.2.0-peer-test-mocks            # test-only; omit for GO-PINS-ONLY
git merge --no-ff fix/v1.2.0-preview-test-list          # test-only; omit for GO-PINS-ONLY

# 2. Gates on the merged branch.
pnpm install --frozen-lockfile
pnpm typecheck && pnpm lint && pnpm knip:check && node scripts/release-smoke.ts
# web production build; client-runtime, mobile and web unit suites.
# Expect only the failures that also occur on release/v1.2.0 (see "Known failures"), fewer with the fixes.
# 2b. Run the build through scripts/dev-t3-serve.sh (bridge) on a port other than 3773 with a scratch
#     base dir, and repeat the web pin check in a background browser. No provider usage is needed.
BUILD=$(git rev-parse HEAD); BUILD12=${BUILD:0:12}; DATE=$(date -u +%Y%m%d)
FULL=0.1.5-v1.2.1.$DATE.$BUILD12.connect1
git push origin release/v1.2.1

# 3. Windows x64 installer, on framework, from a checkout at BUILD.
cd native/resource-monitor
cargo build --locked --release --target x86_64-pc-windows-msvc
cd ../..
cp .env.example .env        # the public Connect config, as in earlier builds (the .env is gitignored)
export T3CODE_DESKTOP_VERSION=$FULL
export T3CODE_DESKTOP_UPDATE_REPOSITORY=Errantial/t3onsteroids
export T3CODE_DESKTOP_REUSE_RESOURCE_MONITOR=true
pnpm dist:desktop:win:x64   # writes release/T3-Code-$FULL-x64.exe, .exe.blockmap, latest.yml

# 4. Source and patch archives.
git -C <bridge> archive --format=zip --prefix=t3onsteroids-1.2.1/ \
  -o t3onsteroids-1.2.1-source.zip v1.2.1
git -C <fork> format-patch 92f12598b7..$BUILD -o patches-1.2.1   # merges are skipped; 5 patches (3 without the fixes)
zip t3onsteroids-1.2.1-t3-patches.zip patches-1.2.1/*.patch

# 5. Bridge paperwork, then the tag (decision 4).
cd <bridge>
git switch release/v1.2.1
git merge release/v1.2.0                 # brings the v1.2.0 notes and status; re-run git merge-tree first
npm version 1.2.1 --no-git-tag-version   # package.json and package-lock.json
# fill the @@...@@ placeholders in docs/releases/v1.2.1.md; add the v1.2.1 section to
# docs/release-status.md; add the publication details to this file
grep -n "@@" docs/releases/v1.2.1.md     # nothing may remain after filling (the header comment is removed)
npm run verify
git commit -am "chore(release): v1.2.1 Pinned Labs"
git tag -a v1.2.1 -m "v1.2.1"
git push origin release/v1.2.1 v1.2.1

# 6. Publish: a draft first, SHA256SUMS.txt uploaded last, digests checked, then publish.
sha256sum T3-Code-$FULL-x64.exe* latest.yml t3-$FULL-linux-arm64.tar.gz \
  t3onsteroids-1.2.1-source.zip t3onsteroids-1.2.1-t3-patches.zip > SHA256SUMS.txt
gh release create v1.2.1 --repo Errantial/t3onsteroids --draft --title "v1.2.1 Pinned Labs" \
  --notes-file docs/releases/v1.2.1.md
gh release upload v1.2.1 --repo Errantial/t3onsteroids <the six assets>  SHA256SUMS.txt
# compare each asset's size and digest with the staged file; latest.yml version, sha512 and size
# must equal the uploaded exe; every download URL must return HTTP 200.
gh release edit v1.2.1 --repo Errantial/t3onsteroids --draft=false
```

**The Linux arm64 archive (step 3b) is a procedure, not one command.** It is built natively on
server-1 (Oracle Linux 9, aarch64), and needs the operator's access to server-1. Follow the v1.1.9
record in `docs/evidence/v1.1.9-release.md`, "Linux":
- a scratch clone at `BUILD` on `/mnt/data` (the root disk is small), the official
  `node-v26.12.1-linux-arm64` checked against `SHASUMS256.txt`, and `nice -n 10`;
- the workspace version set to `FULL` with `scripts/update-release-package-versions.ts`;
- the fork's `cli.ts build-exe` and `scripts/build-cli-archive.ts` stage the tree; the SEA `t3` is then
  replaced by the launcher, `node` and `t3.mjs`, with `lib/libatomic.so.1` bundled;
- verify by extracting to a fresh directory and running `t3 --version` from another directory
  (the generic smoke script cannot check a launcher layout).
