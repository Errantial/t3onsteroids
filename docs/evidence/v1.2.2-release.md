## Merge

The first attempt copied "verified port" files over the merge and erased fork features that git would
have merged cleanly (the SSH remote port range, saved threads, the pin overhaul wiring, fleet update
handlers, among others). It was discarded (kept locally as `backup/v1.2.2-delegate-merge-wip`). The
merge was redone with a native `git merge` of `0517d15c41` into `51ce1bf993`: 95 conflicted files, each
resolved from base, fork and upstream versions, with every other file as git merged it. Merge commit
`b44510b4e8`, then fix commits to the build commit.

Decisions beyond a plain union:

- **Migrations.** Fork migrations moved from 73/75 to 90/91 because upstream now owns 73-89;
  `reconcileChatGptBrowserForkMigration` clears the old fork records. Scratch copy of server-1's live
  v1.2.1 database (727 MB) booted with the new runtime: migrations 73-91 applied, ready in 10 s,
  `databaseMigration: 91`. The copy was deleted; the live service was not touched.
- **ACP usage.** Fork behavior kept for agents that do not declare per-turn usage; the one upstream test
  asserting "unavailable" was rewritten.
- **Sidebar.** One partition implementation (`Sidebar.logic.ts`) with upstream's reorderable-key rule and
  the fork's pin overhaul and saved view.
- **Tokens/sec.** Re-wired into the thread-details Context section (patch 0001 hunks).
- **effect 4.1.** `effect/Crypto` no longer exists; fork code uses `effect/crypto/SecureRandom`.
- **Windows payload guard.** The generated `server-compile-cache` (23 files, upstream's) is excluded from
  the 80-file generic count.
- **Packaging.** The ChatGPT Browser package typechecks with `effect-tsgo` like its siblings; the
  `unenv` peer rule allows the newer prerelease a fresh resolve picks (fixes `release-smoke`).
