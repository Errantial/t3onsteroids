# t3onsteroids v1.1.4

Feed/bootstrap release on the `1.1.1` feature line that publishes a fresh **T3 Code 0.1.5 Windows x64 installer** with the t3onsteroids T3 patch series, **T3 Connect enabled**, and an **auto-update feed** bound to this repository.

## Windows installer

```text
T3-Code-0.1.5-v1.1.4.20261031.98beeb3e80fd.connect1-x64.exe
```

- Base: T3 Code `0.1.5` (`6d450a4284852af137b2f3407fddd89eb76e7644`).
- Fork: ChatGPT Browser fork at `493e87f8f9`, merged with stable `0.1.5`; build commit `98beeb3e80fd`.
- t3onsteroids patch series: `handoff/t3-patches/main-2026-10-29-6d450a42/` applied with `git am --3way`:
  - `0001` optional per-thread tokens/sec readout;
  - `0002` ACP per-turn token usage from the prompt response;
  - `0003` show or reload a thread's ChatGPT tab;
  - `0004` keep pinned threads in activity order when the setting is off;
  - `0005` move the revealed ChatGPT window on-screen;
  - `0006` link fork updates to the fork's release tag.
- T3 Connect: production public configuration baked into the packaged server (`connect1` build):
  - relay `https://relay.t3.codes`
  - Clerk publishable key and JWT template
  - CLI OAuth client
  - `t3 connect status --json` works against the extracted packaged server with no runtime environment variables.
- The installer is **unsigned** and has no code-signing certificate; the update feed does not change that.

SHA-256: `627031FDCEC95709DFF4EE0E3E3D814F8A13706D0AB2FAC80C0F0B338FC4C97E` (314,460,657 bytes)

## Auto-update

- `app-update.yml` is baked in with provider `github`, owner `Errantial`, repo `t3onsteroids`. The app never consults `pingdotgg/t3code`.
- Stream: `latest`. The app's default channel for these versions is `latest`; this fork publishes no `nightly` channel.
- Each release serves `latest.yml` (electron-builder's channel manifest) plus the NSIS installer and its `.blockmap`. The updater reads the newest non-prerelease GitHub release and downloads the installer named in that manifest.
- Behavior is unchanged from T3: startup-delayed/periodic checks, no automatic download or install; the update button downloads first and installs on the second click.
- **Bootstrap:** `v1.1.1`-`v1.1.3` were built without a feed. Install `v1.1.4` once; later `latest` releases update in place.

## What changed in 1.1.4

- **Auto-update feed enabled** for the packaged app (the build now sets `T3CODE_DESKTOP_UPDATE_REPOSITORY=Errantial/t3onsteroids`), including the `latest.yml` release asset.
- **Release links point at the fork tag.** Fork versions embed the release tag (`0.1.5-v1.1.4...`); the update UI now links to `v1.1.4` instead of a nonexistent `/tag/v0.1.5-v1.1.4...`.
- No behavioral change to the `1.1.2`/`1.1.3` features or the `1.1.1` bridge.

## Known limits

- The installer is unsigned; Windows may warn on first manual install. Auto-update itself is not code-signed.
- T3 Connect remote linking/relay access was not exercised end-to-end.
- The bridge has not been live-qualified over T3 Connect.
- Four- and eight-chat concurrency remain parked.
- The installer is Windows x64 only.
