# t3onsteroids v1.1.5

Maintenance release on the `1.1.x` line: the Windows remote-runtime sync no longer flashes a
console window, the tokens/sec readout is on by default, and the SSH bootstrap downloads the
runtime archive from the release tag that actually exists.

## Linux runtime (server-1)

```text
t3-0.1.5-v1.1.5.20261031.d43ad80f4724.connect1-linux-arm64.tar.gz
```

`server-1` is aarch64 and runs the standalone CLI runtime as a user unit
(`~/.config/systemd/user/t3code.service`, `ExecStart=.../versions/<full>/t3 __service-launcher`,
`T3CODE_HOME=/home/opc/.t3-nightly`). The archive unpacks into
`~/.t3-nightly/runtime/versions/<full>/`; the previous directory is kept, and the unit is repointed
at the new one. Built natively on the arm64 host with Node 26.12.1 (`--build-sea`), because
`vp pack` has no linux-arm64 target; see `AGENTS.md` for the exact steps and cleanup.

SHA-256: `722F8557CC72E11D885329ABC2C5713EF593125D3353FFBD15BC037EDD805018` (140,107,186 bytes).

## What changed

### The remote-runtime sync is headless

Two independent causes were fixed:

- **The workaround existed because of a version mismatch.** The desktop passed its full app
  version (`0.1.5-v1.1.4.20261031.98beeb3e80fd.connect1`) to the SSH runner, so the remote
  bootstrap asked for `.../releases/download/v0.1.5-v1.1.4.../t3-0.1.5-v1.1.4...-linux-x64.tar.gz`.
  Only `v0.1.5` is published. The runner now passes the base release version (`0.1.5`), whose
  archive exists, so a fresh SSH environment can bootstrap without pre-seeding.
- **The one-off task ran a console program in the interactive session.** On the machines that
  already have `T3 Remote Runtime Sync`, the app now rewrites the task once at startup: its
  action becomes `wscript.exe //B` running a generated `remote-runtime-sync-hidden.vbs`, which
  starts the original command with window style 0, and the cadence becomes 15 minutes instead of
  one. Both known shapes are recognised (a PowerShell `-File` action and a `.cmd` action); unknown
  shapes are left untouched. The sync itself is unchanged and still runs on schedule.

The migration is idempotent, Windows-only, and only acts when the task exists. It runs on the
first start of `v1.1.5` (the updater restarts the app after installing), so no separate installer
step is needed.

### tokens/sec is on by default

The per-thread readout no longer starts off. The client stores the threads that turned it **off**
(new `t3code:thread-token-rate:v2` key, so the old opt-in list cannot be misread), and the meter
switch keeps working as a per-thread toggle. Providers that report no token total still show
nothing.

## Auto-update

- `app-update.yml`: provider `github`, owner `Errantial`, repo `t3onsteroids`, stream `latest`.
- Bootstrapped by `v1.1.4`; `v1.1.5` updates in place from the app's update button.
- The migration runs from the updated app, not from the installer.
