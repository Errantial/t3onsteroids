# t3onsteroids v1.1.6

Build commit `72a78e666ea1`; full version
`0.1.5-v1.1.6.20261101.72a78e666ea1.connect1`. Assets are named with that full version.

Saved threads, a managed instruction library with per-environment profiles, the per-turn context
slot, and the `t3code-mcp-v2` tool merge with server-1 as the single MCP endpoint. This release is
not rolled out until you approve it.

## Saved threads

A thread can be saved independently of settling or archiving. `savedAt` is its own state, the
sidebar has a Saved filter with one-click restore, and MCP exposes `save_thread`, `unsave_thread`,
and `list_saved_threads`. Unsaving restores the state the thread had before it was saved.

## Instruction files

Settings → Threads manages global and project `AGENTS.md` / `CLAUDE.md` files (and the OpenCode,
Cursor, and custom equivalents).

- **Sync groups** materialize generated copies at provider paths and report missing and drifted
  targets. The generated header records the source id and revision; edit the source in T3, not the
  generated copy.
- **Project profiles** choose one shared file set for every linked environment or a per-environment
  selection. MCP: `get_project_instruction_profile` / `set_project_instruction_profile`; sync
  targets carry an optional `environmentId`.
- **Optional files** attach per thread. A new draft composer has an Instructions picker; the
  selection is attached when the first turn starts. Settings can attach or detach files on an
  existing thread.
- **Materialize** rewrites every sync target and stops on drift unless forced. The new
  `scripts/fleet-config-sync.mjs` mirrors the library between machines with the same rule: a newer
  target revision, or the same revision with different content, stops before writing unless
  `--force`.

## Per-turn context

`RunExecutionService` builds a neutral, ordered, byte-budgeted context after the run ownership
check. Codex receives it as keyed additional context, Claude as leading text after a slash command,
and ACP-based providers as a prompt prefix. Per-thread optional instruction files are the first
registered contributor; the v1.1.7 fleet prompt block can register through the same API.

## MCP merge and the hub

The built-in T3 MCP now carries the missing `t3code-mcp-v2` names and argument shapes, including the
instruction and saved-thread tools and the thread/workspace digests. The full map, paging rules, and
the one intentional omission (an agent cannot approve its own permission request) are in
`docs/releases/v1.1.6-mcp-inventory.md` in the T3 patch series.

The standalone MCP patch is `0.5.1` (`v0.5.1`): it fixes the date-sensitive switched-thread list
fixture and carries the same saved/instruction tools. The built-in MCP on server-1 is the single
endpoint: tools that take `environmentId` route over the existing peer links with that link's
credential and access. There is no second SSH or token layer.
An unreachable peer fails explicitly; it never returns an empty result. Existing standalone
`t3code-mcp-v2` services keep running side by side.

## Also in this release

## Not in this release

Fleet-wide release updates from Settings → About (per-machine version/variant, confirmation,
partial-failure reporting, `fleet_update_status` / `fleet_update`) are the v1.1.7 operational track.
The Labs pin overhaul also lands in v1.1.7: turning off pinned-at-top additionally hides Settle for
pinned threads until they are unpinned. Folding pinned working threads into Working stays on hold.

## Upgrade

Windows: run the installer; the WinSW `t3code` service is stopped, replaced, and restarted by the
fleet updater. Linux: unpack the new runtime next to the current one, point the unit and
`service-state.json` at it, restart, and keep the previous directory for rollback. Updating restarts
T3 and interrupts running threads.

No data migration is required. The instruction library lives under `T3CODE_HOME/instructions` and is
created on first use.
