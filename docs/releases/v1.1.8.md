## Fleet pipeline fix

- **Dev and verification servers stay off `:3773`.** A T3 started inside WSL on the host's loopback
  port shadows the host's own T3 for every loopback client, including the T3 Connect tunnel, so the
  phone reaches the wrong environment. `scripts/dev-t3-serve.sh` runs a throwaway server on `3777`
  or the next free port, with a scratch `~/.t3-dev` base directory, and stops it when the wrapped
  command exits or fails. It refuses `:3773`, `~/.t3`, and `~/.t3-nightly`.
- **`fleet-update.mjs` checks the identity, not just the listener.** For a `windows-ssh` target it
  first finds and stops a managed T3 that T3's SSH bootstrap launched inside that WSL on `:3773`
  (`--keep-wsl-t3` reports it only). After the install it requires
  `127.0.0.1:3773/.well-known/t3/environment` to return the machine's own
  `userdata/environment-id`; a bare listener or another environment id fails the update.
- **Sequential Windows updates.** `updateWindows` is async and the loop now awaits it, so a later
  target cannot install while the previous one is still running and a failure stops the run.
- AGENTS and the roadmap record the app-side follow-up: SSH bootstrap must not default to `:3773`,
  and Connect origin identity must check the environment id.
- The former 0010 update-channel patch is not included; swarm and the pipeline fix add no separate
  update track or channel.

## Swarm

- **Entry points.** `/swarm` in the composer, **Start a swarm** in the command palette, and **start a
  swarm** on a draft's hero. The dialog takes a brief, an optional team cap (3, 5, 8, or let the
  architect decide), and a per-agent worktree option. It inserts an editable architect brief into the
  composer; it does not send the message for you.
- **One orchestrator call.** The agent designs the roster and calls `create_swarm` once. It accepts
  1–12 members with unique keys; each member has its own provider instance, model, options, role,
  isolation, and self-contained task. Members launch through the existing delegated-task path as
  ordinary T3 child threads, so they appear in the parent's agent list and open individually. A
  member can itself call `create_swarm` or `delegate_task` to lead its own sub-team.
- **Partial failures.** A member that fails to launch is returned in `failed` while the rest
  continue; `launched` names every child thread.
- The tool is in the built-in MCP with summary labels in the client, and the agent context budget is
  updated for the larger tool list (`mcpToolListJsonBytes` 55,954).

## Upgrade

Windows: run the installer. Linux: unpack the new runtime next to the current one, point the unit and
`runtime/service-state.json` at it, restart, and keep the previous directory for rollback. Updating
restarts T3 and interrupts running threads.

No data migration is required.
