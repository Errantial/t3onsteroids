## MCP effort level

- **One `effort` for every provider.** `delegate_task` (`target.effort`), each `create_swarm` member
  (`members[].target.effort`), each `create_threads` entry (`threads[].target.effort`),
  `t3_thread_launch` and `t3_thread_send` take a reasoning level such as `high`. The server writes it
  to the option the chosen model advertises: `effort` on Claude, `reasoningEffort` on Codex. Agents
  no longer need the provider's own option id.
- **Sends change the level too.** `t3_thread_send` writes the thread's model selection, so the level
  applies to that message's run and to later turns.
- **Checked against the model.** A level the model does not offer, a model with no effort option, or
  effort given both as `effort` and in `target.options` fails with `invalid_request` naming the
  allowed values. Omitting `effort` keeps the previous behaviour.
- **Visible levels.** `orchestrator_capabilities` reports `effort: { optionId, values, default }` per
  model; thread list items, thread detail, recent runs, created threads and swarm members report the
  model's `options`, so the current level shows without a separate call.
- The agent context budget is updated for the larger tool list (`mcpToolListJsonBytes` 55,954 ->
  56,605). A follow-up commit trims two code comments and drops an unused export so lint and knip
  pass; it changes no behaviour or tool schema.

## Fixes

- **ChatGPT Browser on service-hosted servers.** A background service runs the installed app in node
  mode without `T3CODE_CHATGPT_BROWSER_RESOURCES_DIR`, so the provider reported "The bundled ChatGPT
  Browser runtime could not be resolved" and never started the managed host. Resolution now also
  looks in the executable's `resources/chatgpt-browser`, where the installer ships the payload.
- **SSH launches stay off `:3773`.** SSH-bootstrapped servers pick a port from 3790-3989 and do not
  reuse a remembered port outside that range, such as an older launch on 3773. This is the app-side
  follow-up that v1.1.8 recorded.
- **Connect checks the origin's identity.** Before publishing the tunnel,
  `startManagedTunnelIfOriginConfirmed` reads the loopback origin's `/.well-known/t3/environment`
  and refuses an origin that answers as another environment. `ConnectReachability` reports
  `origin_unreachable`, naming the other environment id, when the public endpoint answers as another
  environment.

## Upgrade

Windows: run the installer. Linux: unpack the new runtime next to the current one, point the unit and
`runtime/service-state.json` at it, restart, and keep the previous directory for rollback. Updating
restarts T3 and interrupts running threads.

No data migration is required.
