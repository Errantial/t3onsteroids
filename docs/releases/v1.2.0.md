# t3onsteroids v1.2.0

Build commit `92f12598b70619dbb9af9ec4827a7660a2aea40b`; full version
`0.1.5-v1.2.0.20261104.92f12598b7.connect1`. Assets are named with that full version.

v1.1.9 plus thread visibility across linked environments, the effort validation pass, and optional
per-environment project roots with repository-key placement. W3/W4 (fleet execution and thread fleet)
were cut from this release because their required Windows↔Windows and Windows↔Linux evidence was
not available on the RC baseline; their code stays on `feat/v1.2.0-peer-exec` for a later release.

## Thread visibility

- Thread ids resolve by exact id, alias, or an 8–35 character prefix on reads; mutations refuse
  prefixes. Results echo the canonical id.
- Thread list and search can span linked environments with a per-link opt-in; archived and subagent
  matches are covered. Deleted-project rows join correctly.

## Effort validation

- Effort is checked against each model's advertised option descriptors. `t3_thread_send` persists
  effort and stays model-stable; `t3_thread_configure` drops an option the new model does not
  advertise and reports `optionsDropped`.
- Pi and Grok `thinking` map to effort; OpenCode `variant` is still not an effort option.
- A peer without `effort-v1` fails `target_capability_missing` before forwarding.

## Per-environment project roots and repository-key placement

- `Project.environmentRoots` stores one workspace root per linked environment in
  `projection_projects.environment_roots_json` (migration 075, default `{}`).
- `get_project_environment_roots` and `set_project_environment_root` read and edit the map; the set
  call needs full access and a linked environment. Project settings has an editable **Environment
  roots** table.
- `t3_thread_launch` accepts a canonical `repositoryKey` (mutually exclusive with `projectId`). The
  caller resolves a local project's key, the peer matches its own live projects, and one match
  launches on that peer project. Zero/several matches return
  `project_not_found_in_environment` / `project_ambiguous_in_environment`; a missing local identity
  returns `repository_identity_missing`. A peer without `thread-placement-v1` fails
  `target_capability_missing`.
- Root enforcement and use-time repository checks remain v1.3.

## Fleet tools cut from v1.2.0

W3 (`peer-exec-v1`, `t3_shell`, `t3_fs_read`, `remoteExecution`) and W4 (`thread-fleet-v1`,
`t3_targets`, `t3_target_use`) are not in this release. No fleet tools or execution settings are
advertised.

## Migrations

- 075 `ProjectionProjectsEnvironmentRoots`: one additive `TEXT NOT NULL DEFAULT '{}'` column.
- 074 remains reserved for W3 receipts and is not present in this release.
- A v1.1.9 build ignores the new column and fields. Future migrations start at 076.

## Upgrade

Windows: run the installer; it updates the installed T3 Code app in place. Linux: unpack the new
runtime next to the current one, point the unit and `runtime/service-state.json` at it, restart, and
keep the previous directory for rollback. Updating restarts T3 and interrupts running threads.

No data migration beyond the additive 075 column is required. Framework remains on v1.1.9; do not
install this release there until separately approved.
