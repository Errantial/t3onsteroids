A small point release on the published v1.2.0 (build commit `92f12598b70619dbb9af9ec4827a7660a2aea40b`,
the fleet-free release without peer-exec). It moves the pin overhaul setting to Settings -> Labs and
makes pinned threads fold into Working under it, on web and mobile. It is built from a new fork
branch `release/v1.2.1` based on that commit.

It changes no server code, no MCP tool, and no database schema: the migration head stays 75, and the
MCP tool list is identical to v1.2.0 (92 tools, 57,907 bytes, same hash). The pin overhaul is off by
default. Swarm v2 was built for this release and then deferred; it is not included. No machine is
rolled out; installs remain manual.

## Pin overhaul

Behind **Settings -> Labs -> Pin overhaul**.

- **Moved to Labs.** The setting leaves General -> Sidebar. The old link to it redirects to Labs.
- **Restore defaults.** "Restore defaults" now resets the setting. Before, it left the setting
  unchanged.
- **Pinned threads fold into Working.** With the overhaul on, a running pinned thread sits in
  Working on web and mobile, gets the same 2-second exit grace as other threads, and then sorts with
  the active list by recent activity. Settle stays hidden for pinned threads, and pinning still
  prevents automatic settling.
- **Mobile.** Mobile has its own "Pin overhaul (Labs)" preference, off by default. Settle is hidden
  for pinned threads in the swipe actions and menus, and the arrange sheet drops its pinned section.
- **Folder sidebar.** It keeps pinned threads on top.
- **Docs.** The sidebar guide now says pinning prevents automatic settling.

## Checks

Measured on `release/v1.2.0` plus the three pin commits (`790a951136`, `13a9cbe3c1`, `edb1a4bf58`):

- Windows: `pnpm typecheck` and `pnpm lint` pass. Client-runtime 141 files / 1,477 tests, web 325
  files / 4,373 tests, and mobile 249 files / 3,001 tests (11 skipped) pass.
- The MCP tool list equals `release/v1.2.0`: 92 tools, 57,907 bytes, the same sha256
  `bf142a56...58ee`. The migration head is 75 on both. The diff touches no server or contracts file.
- Live check in a background browser (web): the switch is in Labs and gone from General; a running
  pinned thread sits in Working without Settle, and it moves up one to two seconds after the run
  ends. This check ran on a build that also contained the deferred swarm code; the pin screens do not
  depend on it.
- Linux (WSL, 2026-11-12): see `docs/evidence/v1.2.1-release.md`, "Linux gates".
- Bridge `npm run verify` (typecheck, lint, 319 tests, package smoke) passed on this branch before the
  version bump and is re-run after it.

## Upgrade

Windows: run the installer. Linux: unpack the new runtime next to the current one, point the unit at
it, restart, and keep the previous directory for rollback. Updating restarts T3 and interrupts
running threads.

No data migration is required.

## Known limits

- The pin overhaul on mobile is not qualified on a device; mobile has no client in the test setup.
- The swarm-free build has not been run live; the live pin check used a build that also had swarm
  code. The pin diff touches only web, mobile and client-runtime files.
- The folder sidebar keeps pinned threads on top even with the overhaul on.
