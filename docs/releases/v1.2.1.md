A point release on the published v1.2.0 (build commit `92f12598b70619dbb9af9ec4827a7660a2aea40b`, the
fleet-free release without peer-exec): Swarm v2 (beta) and the pin overhaul changes. It is built from
a new fork branch `release/v1.2.1` based on that commit. Both features are behind Settings -> Labs, and
everything is off by default. With both off, the MCP tool list is identical to v1.2.0 (92 tools, 57,907
bytes). No machine is rolled out; installs remain manual.

## Swarm v2 (beta)

Turn it on with **Settings -> Labs -> Swarm v2**. With it off, agents get the original
`create_swarm` tool and nothing new is admitted.

- **Queue and admission.** Members beyond the concurrency limits wait and start as slots free up,
  including after the architect's turn has ended. Defaults are 8 running members globally and 4 per
  account. The caps are settings, up to 48.
- **Spreading across accounts.** A member target can list several instances of one provider
  (`anyOf`). The member starts on the least busy healthy account (paused, signed-out or failing
  accounts are skipped) and stays there.
- **Fan-out and shared context.** `sharedContext` is sent once for the whole swarm. A `map` expands
  one task template over rows, up to 48 rows. `swarm_add_members` adds members later. Limits: 12
  members per call, 48 per swarm (retries included).
- **Member contract and result block.** Each member gets its contract in turn context and ends with
  a structured result. Members without `verify` end as claimed done and show as unchecked.
- **Verify.** An optional command runs in the member's checkout when it finishes, with up to 2
  retries by default. It needs Full access on both the architect and the member (see Known limits).
- **Wake policies.** `group` (the default), `failure` and `batch` set when results wake the
  architect. The `/swarm` dialog has a Wake policy field.
- **Compact digests.** Each member's result reaches the architect as a digest of at most 1,024
  bytes. Full results come from `swarm_collect`, marked as data.
- **Follow-up.** `swarm_followup` sends a finished member more work, at most 5 times.
- **Management tools.** `swarm_status`, `swarm_cancel`, `swarm_retry`, `swarm_collect` and
  `swarm_followup`, available only to the architect that started the swarm.
- **Usage limits and failures.** A usage-limited account stops taking new members until reset and
  members can resume by themselves. Two transport failures within a minute pause the account for 5
  minutes. A transient failure is retried once automatically.
- **Budgets.** Per member: 20 turns and 2 hours by default. Per swarm: 240 turns. A swarm or member
  can lower these limits, not raise them.
- **Swarm panel and sidebar chip.** The thread details show counts, accounts, notes, filterable
  members and Open, Stop, Retry and Stop all. The sidebar shows "Swarm - N running - M queued - K
  failed". Both appear only with Swarm v2 on.
- **Notices.** Events that do not need a turn (a paused account, approvals waiting, a used budget,
  a Stop or a detach) reach the architect as notes at the start of its next turn, never as a
  message. Member approvals go to you, not the architect.
- **Stop and detach.** Stop on the architect cancels its swarms. Cancelling its queued wake detaches
  the swarm, after a confirmation. Other interrupts leave the swarm running.

## Pin overhaul

Behind **Settings -> Labs -> Pin overhaul**.

- **Moved to Labs.** The setting leaves General -> Sidebar. The old link to it redirects to Labs.
- **Restore defaults.** "Restore defaults" now resets the setting. Before, it left the setting
  unchanged.
- **Pinned threads fold into Working.** With the overhaul on, a running pinned thread sits in
  Working on web and mobile, gets the same 2-second exit grace as other threads, and then sorts with
  the active list. Settle stays hidden for pinned threads, and pinning still prevents automatic
  settling.
- **Mobile.** Mobile has its own "Pin overhaul (Labs)" preference, off by default.
- **Folder sidebar.** It keeps pinned threads on top.
- **Docs.** The sidebar guide now says pinning prevents automatic settling.

## Fixes

- **Held wakes stay off the client wire.** A held completion wake is sent to clients as
  `settled_only`, so a v1.2.0 mobile client or linked server decodes the records. It was checked
  against the real v1.2.0 contracts.
- **Swarm review fixes.** Examples: notices deliver only what fits and keep the rest pending; a
  stale verify process is killed; a member never resumes after the turn budget is used.

## Upgrade

Windows: run the installer. Linux: unpack the new runtime next to the current one, point the unit
at it, restart, and keep the previous directory for rollback. Updating restarts T3 and interrupts
running threads.

A v1.2.0 database upgrades by adding migrations 076-078 only (the migration head on v1.2.0 is 075).
Installing v1.2.1 and then returning to the v1.2.0 binary: not yet verified.

## Known limits

- Members on other machines are refused in this release (D11).
- `verify` requires Full access on both the architect and the member; Auto is not enough.
- The concurrency caps (8 global, 4 per account) are starting values. Provider rate limits are
  unmeasured until the three-account run.
- Nesting depth is 1: a member may start its own swarm only if the architect set `allowNestedSwarm`.
- A member's reasoning effort is not shown in the panel.
- Detach only exists when a queued swarm wake can be cancelled. Providers that deliver results into
  the architect's running turn, such as OpenCode, never queue one. Use Stop or the panel's Stop all.
- After a server restart, a "Worked for" duration can read longer than the run took.
- A provider-backed swarm run on Linux and the pin overhaul on mobile are not qualified in this release.
- Swarm v2 can be slower than one agent on a few small tasks. It is built for many, slow, or
  separately checked-out tasks.
